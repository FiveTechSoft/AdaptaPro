# Modelo de datos de AdaptaPro

Este directorio define la base de datos local y un conjunto de datos de ejemplo para el flujo de inventario y aprobaciones. El panel `index.html` todavía no los carga ni realiza pedidos reales. `schema.sql` define SQLite; `seed/demo.json` contiene registros de ejemplo en español. Importa los arrays en el orden en que aparecen, con sentencias preparadas dentro de una transacción y `PRAGMA foreign_keys=ON` en cada conexión. `details_json` es texto JSON válido. Los importes son céntimos de EUR, cantidades en unidades del producto y fechas ISO 8601 UTC.

## Flujo de la demo

1. Importa las semillas una sola vez en una base nueva. `SELECT * FROM stock_status WHERE needs_restock=1` muestra SKU-451 con 18 rollos físicos, 12 reservados y 6 disponibles. La propuesta PROP-001 de ALPHA por 80 rollos queda pendiente, coste simulado de 2.720 EUR. No hay compra ni stock nuevo todavía.
2. La persona revisa y decide. En una transacción: actualiza `approval_queue` solo si `status='pendiente'`, rellenando `decided_by`, `decided_at` y `decision_reason`; comprueba que cambió una fila y añade `audit_log` con el actor. Rechazar no cambia existencias. No confundas la aprobación con la recepción física.
3. **Solo para la demo**, tras aprobar, simula explícitamente la recepción: en otra transacción comprueba que la propuesta está aprobada y que no existe ya un movimiento para ella; incrementa `inventory.on_hand` en 80, añade un `stock_movements` positivo con `proposal_id='PROP-001'` y un evento `audit_log` de `recepcion_simulada`. La vista pasa a 86 rollos disponibles (98 físicos, 12 reservados). El dashboard futuro puede leer la vista antes/después. En un ERP real, recepción y aprobación serían pasos separados con verificación de entrega.
4. Un botón «Reiniciar demo» debe reemplazar la base local con una copia limpia de las semillas, no sumar el inventario otra vez. Evita la doble recepción haciendo el paso 3 atómico y usando un ID único determinista del movimiento (por ejemplo `MOV-PROP-001`); una transacción revertida no deja stock a medias.

SQLite en WebAssembly puede ejecutarse en GitHub Pages, que sirve archivos estáticos. Guarda/exporta los bytes de la base en IndexedDB al confirmar cada transacción y rehidrátalos al abrir la página. Si la pestaña se cierra antes de guardar, se perderá esa transacción. Cada navegador/perfil tiene su propia copia: no hay sincronización multiusuario, autenticación, aprobación verificable ni base central. No almacenes datos personales o secretos aquí sin controles adicionales. La implementación de importación, almacenamiento, interfaz y agentes sigue pendiente; estos ficheros por sí solos no convierten el panel actual en funcional.
